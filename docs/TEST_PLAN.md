# Validation and manual smoke test

## Version 0.5 release validation

`npm.cmd run release:check` runs all unit tests and strict TypeScript checks, rebuilds dist, runs the existing browser and media acceptance suites plus `test:selection`, packages the release, and verifies matching source/package/lock/build versions and every packaged byte against dist. Dependency security is checked separately with `npm.cmd audit` so an unavailable registry does not masquerade as a local test failure.

Selection regressions cover all/none/subset semantics, exclusion without losing undisplayed posts, invalid IDs/types, persisted filtering, empty-selection rejection, immutable active scopes, single-post sync-file connection and history import, preserved subsets on rescan, and extending a finished creator folder without generating other posts' tasks. The selected-post Chromium flow uses three controlled posts: save post 1 as ZIP, extract it, choose its real sync.json through the access tab, save only post 2 into that folder, repeat without extra transfers, and connect the same archive on post 3 without a creator-page API request. It verifies exact image bytes, selected-only ZIP metadata, cumulative saved history, one browser ZIP download, and cleanup of temporary files.

Native folder/file dialogs and session permission prompts remain manual checks. On a real creator, repeat the ZIP-to-folder sequence with two individually chosen posts, confirm the source selector and checkboxes stay unchanged after choosing sync.json, and verify unrelated posts are absent. Explicitly choose All posts to verify whole-creator sync remains available. Live creator archives are not downloaded by automated tests.

## Historical run commands (0.1.x)

`npm.cmd run check` runs unit tests, type checking and build. `npm.cmd run test:browser` is the recorded-fixture scenario. `npm.cmd run test:browser -- --live` repeats the public-network smoke test. `npm.cmd run recon` refreshes sanitized real fixtures and measured pagination. Reports and screenshots are saved under `artifacts/`.

Add `--native-downloads` to either browser scenario to verify the real relative filenames and directory structure, rather than the automation download override. The test writes a new isolated profile with its downloads folder inside that run's artifact directory; it never uses the user's profile.

`npm.cmd run test:browser -- --server-root --native-downloads` exercises the full server-root workflow with captured navigation, recorded message pages and controlled responses. Every listed channel is checked, including zero-count channels; a fixture API 403 remains independent. **Download All Images** runs the complete available-thumbnail queue and saves channel manifests, including empty/error channels. `--server-root --live --native-downloads` validates real server-root redirect handling, page/API channel counts and creation of a job containing all channels; it cancels that job before a full live-server transfer. `node scripts/server-recon.mjs` refreshes the sanitized channel-navigation fixture.

`npm.cmd run test:browser -- --folder --brave` runs folder saving against the installed Brave with File System Access API enabled. `--server-root --folder` exercises the full 65-channel fixture batch in Chromium. These scenarios deliberately enable browser Save prompts, count one picker call, forbid the browser download API, verify actual saved-file checksums and JSON manifests, and persist a real directory handle across a worker shutdown/restart. Headless tests replace the OS picker with an OPFS directory handle; choosing an external OS directory and its native permission prompts remain manual checks.

## Historical manual checks (0.1.x)

1. Load or reload `dist` unpacked in Chrome, Edge or Brave, and refresh the Kemono server tab.
2. Open the popup; verify both detected snowflakes match the URL exactly.
3. Scan the reference channel with Thumbnail Only. Expect currently 32 messages and 57 images; a `post_count` discrepancy is expected and should remain a warning.
4. Export CSV/JSON before downloading. Verify raw timestamps, thumbnail URLs, null fabricated attachment IDs, provenance and coverage.
5. In Brave, enable `brave://flags/#file-system-access-api` and relaunch. Open the dashboard and choose a real destination folder once; approve write access. Download images and confirm there are no per-image Save or multiple-download prompts, including for manifests and exports. Confirm recognizable images and deterministic server/channel folders in the selected directory. Inspect actual format (`.jpg` can be correct for a `.png` source URL).
6. Pause/resume and close/reopen the popup. Stop the worker from the extensions page, then reopen the dashboard; completed files should remain completed. Restart Brave and grant folder access again if requested; the batch should pause safely until access is restored. Separately select Browser downloads, disable Ask where to save each file, allow automatic downloads for the prompt's origin, and check interruptions with that browser configuration.
7. Scan two selected channels, including a failing or empty one. Verify each has independent status and checkpoint. Retry failures, cancel a separate job and export partial results.
8. Optionally grant original-host permission and test Best Available/Original Only on observed URLs. Unavailable originals must be logged; Original Only must not silently save thumbnails.
9. Paste the server-root URL, discover all channels, and verify **Entire server** selects every page/API channel. Scan All Channels, then Download All Images. The server-root redirect to the first channel must not force current-channel-only behavior. Changing individual checkboxes must switch the scope to Selected channels.

Full-server media availability, all browser variants, arbitrary legacy formats, original-node availability and a full operating-system/browser crash mid-transfer are not established by the automated results above.

ZIP regression tests cover ZIP64 compatibility, stored image bytes and CRC, unsafe/duplicate paths, cancellation, asynchronous packaging, one browser download, cancelled/interrupted saves without refetch, worker/offscreen recovery, and staged-to-downloaded commit only after ZIP completion. Both use default Brave folder settings, deliberately enabled Save prompts and blocked automatic downloads; the one native Save dialog is replaced for headless automation, while the requested production `saveAs: true` is asserted.
